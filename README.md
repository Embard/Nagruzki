# Nagruzki — расчёт водопотребления

Версия от 12.10.2026. Исправления расчёта и выбранный владельцем второй вариант интерфейса.

## Запуск

Распакуйте архив и откройте `index.html`. Для GitHub Pages замените файлы сайта всем комплектом и обновите страницу Ctrl+F5. Сборка не требуется. JSZip и Word-шаблон включены для локального экспорта.

## Что убрано

- Отдельный расчёт канализации, его настройки и текст в отчётах.
- Ввод технологических максимумов и прибавление этих значений к итогам.
- Добавленные поля N, N ХВС/ГВС, часовой загрузки, отдельного числа поливок и дополнительные пояснения.
- Общий расчёт среднего расхода через Qсут/24. Для обычных строк восстановлено Qсут/T, общий итог — сумма по строкам. Для полива и катка сохранено прежнее отдельное правило среднего расхода исходного сайта.

Набор исходных данных сохранён. Название поля количества зависит от выбранного потребителя: для общепита — «Блюд в сутки», для полива — «Площадь F, м²». Поливки задаются в прежнем поле T/n, которое для полива подписано «Поливок в сутки». Согласованный ручной ввод пожарных расходов с основанием сохранён.

## Сохранённые исправления

- Дробные U, T и ψ не теряются и не округляются при сохранении и повторном редактировании. Для блюд сохраняется исходная формула Uчас = Uсут / (T × ψ).
- Магазин с примечанием «20 м²» не попадает в расчёт полива; переименование строки не меняет формулу.
- Суточный расход полива учитывает число поливок.
- Исправлены каталожные данные зрителей бассейна и единицы пополнения бассейна.
- Для групповых душевых сохранён расчёт одновременной работы сеток.
- Промежуточные эквивалентные расходы прибором не округляются; неполные или недопустимые исходные значения не заменяются нулём.
- Сохранены загрузка выбранной строки, исправления сохранений и локальный Word-экспорт.

После удаления отдельного ввода N восстановлен исходный расчёт коэффициентов по NP и NPhr из таблицы Б.2 с линейной интерполяцией. Автоматический переход к Б.1 из расширенной версии убран; применимость Б.2 к конкретной системе определяется вне этой формы. При NP > 2000 граничное значение не подставляется.

## Сохранённые расчёты

Прежние ключи localStorage сохранены. При открытии расширенной версии её дополнительные поля исключаются из рабочих данных и больше не влияют на результат. Число поливок переносится обратно в поле T/n. Перед преобразованием черновика создаётся резервная копия `-before-v3`.

Ручные нормы и согласованные пожарные расходы сохраняются. Для пополнения бассейна из самой первой версии требуется повторно ввести вместимость в м³, поскольку исходная размерность была другой. Старые автоматически определённые пожарные расходы требуют ручного ввода.

## Проверка

При установленном Node.js: `node tests/calculation.test.cjs`.
Проверки охватывают средние расходы при разных T, блюда, сохранения, исключение удалённых полей, коэффициенты и отчёты. Данные старой EXE-программы в каталог не перенесены.

## Интерфейс

Выбранный вариант №2: светлый фон, зелёные акценты, таблица на всю ширину и редактирование непосредственно под выбранной строкой. Внизу — общая таблица итогов ХВС, ГВС и общего расхода. Реквизиты отчёта и подробный расчёт по умолчанию свёрнуты.

«Новая строка» включает режим добавления. При редактировании доступна кнопка «Применить изменения», «Отмена» возвращает сохранённые значения. Неприменённые изменения отмечаются в заголовке; экспорт и именованное сохранение требуют сначала применить или отменить их. Переключение строки с правками требует подтверждения их отмены.

Шрифт Noto Sans и значки Bootstrap Icons поставляются локально с лицензиями; подключения к CDN при работе не нужны. На узком экране форма перестраивается в одну колонку, таблица итогов прокручивается внутри своего блока.
